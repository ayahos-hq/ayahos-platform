## What this change adds

Each item below closes part of a live check once the runtime key is accepted. None of them changes
an authority boundary.

- `GET /v1/runtime/health` gains `database`: the store's applied schema version (read on each call,
  not cached from boot), the build's expected version, and the retention backlog (terminal requests
  due for archival and archived events due for purging, each counted up to 10 000). A mismatch or an
  unreachable store reports `unhealthy` and makes health `degraded`. `scripts/live_release_smoke.py`
  adds a `database_schema` verdict from it.
- `scripts/start-dual-lineage.sh` runs one bounded `python -m dual_lineage.db retention` pass after
  migrations when `DUAL_LINEAGE_SPINE_RETENTION_ON_START=true`; `render.yaml` sets it. The pass is
  limited to 60 s, its JSON counts go to the service log, and a failure is logged
  (`spine.retention_failed`) without stopping the API.
- `DELETE /v1/rag/documents/{document_id}` (runtime key, same principal as ingest). Ingest reports
  `chunks`, `embedded_chunks`, and `indexed_chunks`; `/v1/rag/stats` adds those totals and
  `pgvector`.
- `scripts/live_rag_smoke.rb` (Ruby standard library only; CircleCI `production-rag-smoke`):
  requires the expected SHA, RAG enabled, an embedder, and pgvector (each requirement can be
  relaxed), ingests one random-token probe, requires it embedded and indexed, retrieves it,
  deletes it, and checks it is gone. It waits out a 429 using `Retry-After` because the rate-limit
  smoke fills the same bucket in parallel.
- `scripts/live_workflow_smoke.rb` requires authenticated health to report `LIVE_EXPECTED_SHA`
  before it queues its job, and records `api_build_sha`. Before this, a pass did not show which
  revision it ran against.
